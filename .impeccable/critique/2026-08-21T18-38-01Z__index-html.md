## Overall Impression

This is a confident, specific execution of "The Shipping Forecast" concept — the colour discipline, the hero exception, the real photography all hold up under scrutiny, including numerically (contrast ratios computed directly from the DESIGN.md hex values all clear WCAG AA with room to spare). The biggest opportunity is that the page's own funnel logic — carefully redesigned and documented as "lead with the Retreat, route it to a conversation, not a purchase" — gets contradicted at the one place all three tiers sit side by side: the comparison table sends the Retreat CTA to a cold `mailto:` link instead of the booking-call path the hero promises. That, plus an invisible-but-tabbable nav breaking the site's own stated accessibility discipline, are the two issues most worth fixing before anything else here.

## What's Working

1. **The hero-only colour exception is implemented precisely.** `#e0a999` dusty rose is used only inside `.bl-hero__title em`; every other `em` on the page correctly uses sitewide signal red `#a8362b`. An easy rule to blur under deadline pressure — it wasn't.
2. **Photography and alt text are genuinely specific.** Named lochs, a named dog, a real workshop and weavers' sign, each captioned with information rather than filler — this is what makes the "real over staged" product principle credible rather than aspirational.
3. **Colour discipline holds up numerically.** Computed contrast: ink-muted-on-paper 6.31:1, signal-on-paper 5.67:1, signal-on-paper-deep 5.0:1, ink-on-paper 12.67:1 — all comfortably clear WCAG AA despite a deliberately low-saturation palette that could easily have failed if handled carelessly.

## Priority Issues

**[P1] Retreat CTA breaks the site's own confirmed funnel logic**
- **Why it matters**: PRODUCT.md documents a deliberate, tested decision (2026-08-18, replacing an underperforming funnel): the Retreat is high-commitment, so its CTA should be a free discovery call, while Checkpoint/Breakthrough get direct self-serve booking. Every CTA on the page honours this — hero, nav, FAQ copy all point to `/book-a-discovery` — except the comparison table's Island Retreat row, which links to `mailto:booking@claritylab.uk?subject=...` instead. That's a colder, higher-friction path (compose an email, wait for a reply) for the exact tier the whole page is built to route into a conversation, at the exact moment a visitor is comparing all three tiers side by side.
- **Fix**: Point that CTA to `/book-a-discovery` like every other Retreat touchpoint on the page. If the mailto is intentional as a secondary path, give it a visually distinct treatment rather than the identical `bl-table__cta` styling as "Book →" — right now nothing signals the two links behave differently.
- **Suggested command**: `/impeccable polish`

**[P1] Keyboard focus lands on four invisible nav items before any visible content**
- **Why it matters**: `bulletin.js` hides the nav pre-scroll via `opacity: 0; pointer-events: none` (`.bl-nav--hero-mode`). `opacity: 0` does not remove an element from the tab order — only `pointer-events: none` blocks clicks. A keyboard user who doesn't use the skip link tabs through four fully invisible, focusable links (site mark, Blog, Podcast, "Free discovery call") with **no visible focus ring**, since opacity:0 hides the outline too, before reaching the hero's real CTA. This directly undercuts the site's own non-negotiable accessibility commitment (PRODUCT.md: "Accessibility is non-negotiable; it is not a visual identity").
- **Fix**: Hide with `visibility: hidden` (paired with `visibility: visible` when `.is-visible` is added) so the nav also leaves the tab order during hero-mode, or toggle `tabindex="-1"` in the same JS that toggles visibility. Note: the no-JS fallback is already correct — without `bulletin.js`, the nav never gets `.bl-nav--hero-mode` at all and stays visible from load — so the fix needs to preserve that path untouched.
- **Suggested command**: `/impeccable harden`

**[P1] Mobile comparison table has no scroll affordance**
- **Why it matters**: Confirmed against the actual iPhone 12 mini production screenshot — at rest, only the "Checkpoint" column is visible; Breakthrough and Island Retreat are clipped off-screen with no fade, arrow, or caption suggesting more content exists. First-time mobile visitors — the device class most first visits likely arrive on — may never discover the Retreat comparison at all.
- **Fix**: Add a trailing-edge gradient mask on `.bl-table-wrap`, and/or a small mono caption ("swipe to compare →") beneath the H2 on narrow viewports.
- **Suggested command**: `/impeccable adapt`

**[P2] No reassurance sits beside the £1,450 ask**
- **Why it matters**: The Investment row for Island Retreat carries identical visual weight and mono treatment to the £65 Checkpoint row, with zero supporting copy. The one relevant testimonial (James C., "The retreat was a game-changer") sits a full section later, past "Who is this for?" — not adjacent to the price. The FAQ repeats the number a third time with still no qualitative reassurance (what's included, group size, refund terms). For the only non-self-serve, highest-commitment purchase on the site, the moment of the ask is the flattest, least-supported moment on the page.
- **Fix**: Attach a one-line qualifier to that table cell or column header (spots per season, what's included), or pull the James C. quote up next to the table.
- **Suggested command**: `/impeccable clarify`

**[P2] Misaligned headings from a CSS class-stacking bug**
- **Why it matters**: `<div class="bl-section__inner bl-prose">` combines two classes whose `max-width` rules collide — `.bl-prose` (40rem) wins over `.bl-section__inner` (68rem) by source order — so "What if I can't come to Scotland?" renders narrower and more indented than "We offer two types of remote problem-space work" directly below it in the same section. Confirmed in the desktop screenshot: the two H2s' left edges visibly don't line up. This reads as an accidental bug, not an intentional device — nowhere else on the page does this offset recur.
- **Fix**: Wrap the prose text in its own inner div instead of stacking classes on `.bl-section__inner`.
- **Suggested command**: `/impeccable polish`

## Persona Red Flags

**Sam (Accessibility-dependent)**: The invisible-but-focusable nav items above is the concrete failure — a keyboard-only user tabbing from page load hits four dead stops with no visible focus indicator before reaching real content. Secondary: external links (`target="_blank"`, `mailto:`) carry no textual or ARIA cue that they leave the page or hand off to another app.

**Casey (Distracted mobile user)**: The comparison table's undiscoverable horizontal scroll (above). Also, the Retreat's `mailto:` CTA is worse specifically on mobile — many mobile Safari users have no configured Mail app, so tapping "Enquire →" can silently fail or dead-end, for the exact tier the hero is built to sell.

**Jordan (Confused first-timer)**: Lands on a hero with one CTA ("book a free call") before learning that cheaper self-serve options (Checkpoint £65, Breakthrough £495) exist several scrolls down. A first-time visitor genuinely unsure whether a call is warranted has no early signal that lighter-touch, self-serve options are available before being asked to commit to a call.

## Minor Observations

- The FAQ pricing table's `<th>` cells lack `scope` attributes, unlike the disciplined `scope="col"`/`scope="row"` used in the main compare table — a small semantic inconsistency between two tables doing the same job.
- Native `<details>`/`<summary>` for the FAQ means it works with zero JS dependency — a good, quiet strength for the no-JS edge case.
- Light consulting jargon ("problem-space work," "ideating," "diagnostic") surfaces in paragraph two, ahead of where the page has earned that register for the "ordinary humans" half of the audience.
- Pricing is stated three separate times (cards, compare table, FAQ ledger) with no cross-reference — a minor working-memory cost as visitors reconcile identical numbers presented in three visual registers.

## Questions to Consider

- What if the comparison table's column order matched the funnel's stated priority — Retreat first, not last — since right now the table quietly walks cheapest-to-priciest, undercutting the hero's "lead with the Retreat" decision the moment a visitor reaches the one place all three tiers sit side by side?
- What if the £1,450 cell carried one line of concrete context (spots per season, what's included) the way a shipping forecast pairs a number with a condition, instead of sitting in a mono grid indistinguishable in weight from the £65 row?
- What if the nav's hero-mode hide used `visibility` instead of `opacity`, so the deliberate "chrome-free first viewport" decision didn't cost keyboard users four invisible stops before the page's first real interactive element?
